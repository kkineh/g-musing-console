# 뮤징 디자인 원칙

musing-designer가 검증에 쓰는 기준이다. 뮤징은 디자인 시스템을 만들어 가는 중이라 항목마다 상태가 있다.

| 표시 | 뜻 | 디자이너의 처리 |
|---|---|---|
| [현행] | 지금 코드가 이미 대부분 따르는 것을 글로 옮김 | 어기면 FAIL, 고친다 |
| [확정] | 사용자가 결정한 것 (날짜 기록) | 어기면 FAIL, 고친다 |
| [제안] | 근거는 있으나 사용자가 아직 확인하지 않은 것 | 어겨도 FAIL 아님. [의견]으로 보고 |
| 결정 대기 (K) | 선택지가 갈려 사용자가 정해야 하는 것 | **고치지 않는다.** 위반 위치만 `--open`에 적는다 |

새로 발견한 혼동(같은 것을 두 이름으로 부름, 같은 역할에 두 스타일 등)은 직접 정하지 말고 `--open`에
"K 추가 제안: 현황 / 선택지 / 추천"으로 적는다. 결정이 나면 메인 에이전트가 이 파일을 고쳐 [확정]으로 옮긴다.

## 0. 제품 [확정]

뮤징은 SR(서비스 요청)을 붙여넣으면 엔진이 저장소와 DB를 읽어 **근거와 함께** 답하는 사내 콘솔이다.
쓰는 사람은 SR을 처리하는 담당자와 답변을 채점하는 관리자다. 매일 오래 켜 두는 업무 도구다.

- 답보다 근거가 먼저 믿음을 만든다. 근거(참조 파일, DB 조회, 처리 단계)는 답과 같은 화면에서 찾을 수 있어야 한다.
- 조용한 도구. 장식은 줄이고 상태와 숫자로 말한다.

## 1. 정보·흐름

| ID | 상태 | 규칙 | 검증 질문 |
|---|---|---|---|
| U1 | [현행] | 같은 숫자는 어디서 보든 같은 기준으로 센다 | 목록 카드의 건수와 들어간 화면의 건수가 같은가 (사례: Wiki 홈 `규정 2` → 분류 화면 `0건`, 2026-11-22 수정) |
| U2 | [현행] | 빈 상태는 왜 비었는지와 다음에 할 수 있는 것을 보여준다 | "없습니다"만 있고 갈 곳이 없는 빈 화면이 아닌가. 하위에 내용이 있는데 "없음"으로 보이지 않는가 |
| U3 | [현행] | 상태(진행 중·사용자 답변 대기·실패·취소·완료)는 색과 글자를 함께 쓴다. 색만으로 구분하지 않는다 | 흑백으로 봐도 상태를 알 수 있는가 |
| U4 | [현행] | 기다림 표시는 실제로 기다릴 때만. 진행 문구는 `~ 중…` 형식 (`저장 중…`, `엔진 처리 중…`) | 즉시 끝나는 동작에 로딩 표시를 붙이지 않았는가 |
| U5 | [현행] | 내부 코드값(`LOGIC_REVIEW`, `WAITING_INPUT`, `done` 등 enum·API 필드명)을 화면에 그대로 내보내지 않는다. 라벨은 `lib/engine.ts`의 `chatTypeLabel` 같은 매핑을 거친다 | 화면에 영어 대문자 코드가 보이지 않는가 |
| U6 | [현행] | 한 영역의 주 행동은 하나다. 주 행동만 `bg-accent` 채운 버튼, 나머지는 보조 스타일 | 한 카드에 채운 버튼이 둘 이상 있지 않은가 |
| U7 | [현행] | 버튼 라벨은 누른 뒤 일어날 일을 말하는 동사로 (`저장하고 다음`, `답하고 이어가기`) | 라벨만 보고 결과를 예측할 수 있는가 |
| M1 | [현행] | **알림 장치는 깔끔함보다 우선.** 목업 엔진 동작 표시(`목업으로 동작 중`), 엔진 응답 없음, 처리 실패, 채점 덮어쓰기 안내, 되돌릴 수 없는 작업(삭제·식별자 변경 불가) 안내는 항상 보이고 약하게 만들지 않는다 | 이 수정으로 경고가 작아지거나 접히거나 사라지지 않았는가 |
| M2 | [현행] | 동작·데이터 흐름·서버 액션·API 호출·조건 로직은 바꾸지 않는다. 디자인 수정은 마크업·클래스·문구·토큰에 한정 | diff에 상태·이펙트·액션 변경이 없는가 |
| M3 | [제안] | 엔진·서버 오류 원문은 일상어 한 문장 뒤에 둔다. 지금 `turn-card.tsx`는 `turn.error`가 있으면 원문만 보여준다 | 원문(`엔진이 500로 응답했습니다` 등)만 덩그러니 보이지 않는가 |

## 2. 문구

| ID | 상태 | 규칙 |
|---|---|---|
| W1 | [확정] | 말투는 합니다체 (`없습니다`, `저장합니다`). 해요체·한다체를 쓰지 않는다. 버튼·placeholder의 명령형(`붙여넣으세요`, `이어서 물어보세요`)은 허용. 사용자에게 던지는 질문(`무엇을 확인할까요`)과 채점 기준 질문(`~맞는가`, `lib/scores.ts`)도 예외 ([확정] 2026-11-22) |
| W2 | [현행] | 용어는 아래 "용어집"의 확정 이름만 쓴다. 결정 대기 용어는 바꾸지 않는다 |
| W3 | [현행] | 페이지 설명문은 한 문장, 이 화면에서 하는 일을 말한다 (`엔진 상태와 처리 현황, 답변 품질을 함께 봅니다.`) |
| W4 | [제안] | 입력 placeholder는 무엇을 넣는지 말한다 (`SR 내용을 붙여넣으세요`). 라벨을 placeholder로 대신하지 않는다 |

## 3. 시각

토큰 원본은 `src/app/globals.css`. 판정 전에 반드시 읽는다.

| ID | 상태 | 규칙 |
|---|---|---|
| V1 | [현행] | 색은 토큰만 (`bg-surface`, `text-text-2`, `border-line`, `bg-accent-soft` …). 컴포넌트에 hex·`rgb()`·Tailwind 기본 팔레트(`text-gray-500`, `bg-blue-600`) 금지. 토큰 투명도 표기(`bg-accent/10`)는 허용. 차트는 `var(--color-*)` |
| V2 | [현행] | 색의 의미. `accent`=주 행동·선택됨·강조 숫자·완료(`good`은 `accent`와 같은 파랑, [확정] K6) / `warn`=사용자 답변 필요·주의(되묻기, 오래 걸림, 채점 대기) / `danger`=실패·파괴적 행동(삭제는 hover에서만 붉게) / `text-3`=메타 정보. 다른 의미로 빌려 쓰지 않는다 |
| V3 | [확정] | 글자 크기는 `globals.css`의 크기 토큰(`text-label`, `text-caption` …)만 쓴다. `text-[Npx]` 임의값 금지. 새 크기가 필요하면 고치지 말고 `--open`에 적는다. SVG의 `fontSize` 속성은 예외 |
| V4 | [현행] | 반경: 카드·패널 `rounded-2xl` / 카드 안 상자 `rounded-xl` / 버튼·입력·목록 행 `rounded-lg` / 배지·작은 칩 `rounded-md` / 알약·점 `rounded-full`. `rounded-[Npx]` 새로 만들지 않는다 |
| V5 | [현행] | 그림자는 토큰만: 카드 `shadow-card-sm`, 떠 있는 것(팝오버·드롭다운) `shadow-card-lg`. Tailwind 기본 `shadow-sm`·`shadow-lg`는 쓰지 않는다 (기존 사용처는 고칠 대상) |
| V6 | [현행] | 라이트·다크 둘 다에서 확인한다. 다크 전용·라이트 전용 색을 컴포넌트에 직접 쓰지 않는다 |
| V7 | [현행] | 숫자(건수, 점수, 시간, 토큰)는 `font-mono tabular-nums`. 단위(건, 점, 초, 개)를 붙인다. 예외: 사이드바 트리의 건수는 숫자만 ([확정] 2026-11-22). 시간·날짜는 `lib/format.ts`(`formatDate`, `formatDateTime`, `formatTime`, `formatDuration`)로만 |
| V8 | [현행] | 아이콘은 인라인 SVG, `viewBox="0 0 16 16"`, `stroke="currentColor"`, `strokeWidth` 1.5, 크기 15px 안팎. 아이콘 라이브러리·이모지를 섞지 않는다. 장식용 아이콘 금지 |
| V9 | [확정] | 본문 폭은 두 가지. 읽고 쓰는 화면(홈, 대화, 채점, 계정·회원사 관리)은 `mx-auto max-w-[760px]`, 목록·대시보드·Wiki는 `AppShell`의 900px 그대로. 예외: 설정의 좁은 폼 `max-w-[560px]`. 다른 폭을 새로 만들지 않는다 |
| V10 | [현행] | 새 장식 효과(그라데이션, 파티클, 글로우, 기울기) 추가 금지. 배경 점 격자(`body`)는 현행 정체성으로 유지 |
| V12 | [확정] | 관리 목록 행(계정·회원사)은 열마다 고정폭을 줘서 행끼리 입력칸·버튼 시작점이 맞는다. 있다 없다 하는 버튼(삭제)도 자리를 비워 둔다 |
| V11 | [현행] | 레이아웃 치수(`w-[236px]`, `grid-cols-[1fr_320px]`)와 모션 값(`active:scale-[0.98]`)은 토큰 대상이 아니라 허용 |
| V13 | [확정] | 에러 화면(404·403·500·503)은 `components/error-art.tsx`의 `ErrorScreen` 하나로 만든다. 제목은 `text-title-sm font-bold`, 설명은 `text-body-sm text-text-2`: 그림(점·선으로 그린 코드 숫자)이 제목 역할을 하므로 페이지 제목(`text-title`)을 쓰지 않는다. 글자 모양과 배경 점 배치는 사용자가 고른 것이라 디자이너가 바꾸지 않는다 ([확정] 2026-11-22) |
| V14 | [확정] | 버튼 상호작용 기준. (1) 손가락 커서는 `globals.css`의 `button:not(:disabled)` 규칙이 준다. 컴포넌트에 `cursor-pointer`를 새로 붙이지 않는다(`label`·`summary`처럼 button이 아닌 클릭 요소는 예외, 기존 코드의 중복은 고치지 않아도 된다). (2) 테두리 있는 보조 버튼의 hover는 `hover:border-gray-node-line`(글자색을 올리려면 `hover:text-text`)로 통일하고 배경은 바꾸지 않는다. 테두리 없는 아이콘·텍스트 버튼은 `hover:bg-surface-3` 또는 `hover:bg-surface-2` ([확정] 2026-11-22) |

### 크기 토큰 [확정]

| 토큰 | 크기 | 역할 |
|---|---|---|
| `text-display` | 30px | 대시보드 핵심 숫자, Wiki 문서 제목 |
| `text-title` | 27px | 페이지 제목 (h1) `font-bold leading-[1.25] tracking-[-0.03em]` |
| `text-title-sm` | 22px | 하위 화면 제목 (h2) `font-bold tracking-[-0.02em]`, 대시보드 지표 숫자 |
| `text-heading` | 18px | 문서 안 제목, 강조 숫자, 로그인 로고 글자 |
| `text-lead` | 15.5px | 카드 제목 `font-semibold`, 답변·문서 본문 |
| `text-body` | 14.5px | 기본 본문 (body), 페이지 설명 `text-text-3` |
| `text-body-sm` | 14px | 목록 행, 입력창 |
| `text-label` | 13px | 섹션 제목 `font-semibold text-text-3`, 주 버튼 `font-semibold`, 패널 머리글(대시보드 카드 제목) |
| `text-caption` | 12.5px | 메타·보조 (작성자·날짜), 배지, 작은 컨트롤(행 안 보조 버튼·select·작은 입력) |
| `text-tiny` | 11.5px | 작은 칩, 사이드바 건수, 아바타 글자 |
| `text-micro` | 10.5px | 사이드바 그룹 이름 `font-bold tracking-[0.05em] text-text-3`, 키 표시(kbd) |

같은 역할인데 다른 토큰이면 FAIL.

## 5. 결정 대기

디자이너는 이 항목들을 고치지 않는다. 메인 에이전트는 작업 중 해당 항목에 걸리면 사용자에게 묻는다.

| K | 무엇을 | 현황 | 선택지 | 추천 |
|---|---|---|---|---|
| K9 | 이력 행 `되묻기` 태그 색 | `accent`. V2는 `warn`=사용자 답변 필요 | 지난 기록이라 `accent` 유지를 V2에 명시 / `warn`으로 | `accent` 명시 (지금 답을 기다리는 건 아니므로) |
| K10 | 설정 화면 `로그인은 회사 MS 계정으로 합니다` | 지금 로그인은 아이디·비밀번호. 사용자: MS 계정 도입 예정 | 도입 때까지 그대로 / 도입 전까지 현행 방식으로 | 도입 시점에 다시 확인. 디자이너는 고치지 않는다 |
